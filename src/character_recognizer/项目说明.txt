这个项目本质上是离线手写汉字分类器 + 简单多字切分流程，适合替换“单行/短句中文手写识别”的百度 OCR 场景。

代码结构（按职责）
config.py：统一命令行参数（数据目录、模型类型、batch、epochs、结果目录等）。
dict.py：从 .gnt 数据集中生成 char_dict（字符 -> 类别索引）。
MyDataset.py：解析 CASIA-HWDB 的 .gnt 文件，做二值化、缩放、可选增强，供训练/测试使用。
model.py：模型定义（ResNet/ResNet18/ResNet34/VGG/LeNet/CNN），输出 3755 类。
train.py：训练主流程（加载数据、训练、每 5 epoch 存权重、记录指标并画图）。
test.py：测试流程，输出 Acc/F1/Recall。
mul_char.py：多字符切分（轮廓检测 + 合并近邻区域），输出 result/output_chars/char_*.png。
recognize.py：加载训练好的模型，识别单字符图，或按序识别 output_chars 并拼成字符串。
result/：模型权重和结果图；data/：训练数据与字典；sentence_img/：待识别图片。
使用说明（最短路径）
安装依赖
pip install -r requirements.txt

准备数据
把 HWDB 数据放到默认目录（./data/HWDB1.1trn_gnt、./data/HWDB1.1tst_gnt）。

生成字典（首次必须）
python dict.py

训练模型
python train.py --model ResNet --epochs 50 --batch_size 512

测试模型
python test.py --model ResNet

推理

单字：你可以直接调用 recognize.py 里的 process_image(path)
多字：先 python mul_char.py 切字，再 python recognize.py 拼接结果
替换百度 OCR 的方法（推荐做“适配层”）
你原项目大概率是“调用百度接口 -> 返回文本字符串（及可选置信度/框）”。
建议不动业务层，新增一个本地 OCR 适配器，保持同样调用方式。

1) 定义统一接口（先和旧代码对齐）
例如旧代码是：

输入：图片路径/图片二进制
输出：{"text": "...", "words_result": [...], ...}
那你新增本地实现：

输入仍然是图片路径/ndarray
输出尽量模拟百度结构（至少保留 text）
2) 单字/多字路由
单字符图片：直接走 process_image
多字符图片：先走 charSeperate 切分，再逐字识别并拼接
3) 在业务里切换提供者
用配置开关：

OCR_PROVIDER=baidu（旧）
OCR_PROVIDER=local_hwdb（新）
业务代码只依赖统一接口，不关心底层是百度还是本地模型。

5) 注意点（替换时最关键）
这个项目是分类模型，不是通用场景 OCR；对复杂背景、印刷体、版面检测不如百度稳定。
目前多字识别依赖轮廓切分，适合“字距较清晰”的图。
标签空间固定 3755 类，超出字表会识别失败或错字。
推理前要保证与训练一致的预处理（灰度、二值化、尺寸 64x64）。
